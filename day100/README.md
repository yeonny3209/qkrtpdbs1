# DAY 100

소행성 충돌로 이름 없는 행성에 불시착한 조종사가, 낮에는 자원을 캐고
밤에는 외계 거미를 피하며, **100일 안에 탈출선을 재조립해** 지구로
돌아가는 탑다운 생존 로그라이크.

기획서(v1.0)를 그대로 구현했습니다. 아래는 만들면서 내린 판단과,
**기획서가 "먼저 깨질 것 같다"고 지목한 가정을 실제로 재 본 결과**입니다.

```bash
npm install
npm run dev
```

---

## 한 판이 어떻게 굴러가는가

하루는 **5분**입니다. 낮 3분, 밤 2분.

낮에는 나무를 패고 고철을 줍고 사냥을 합니다. 낮 170초에 사이렌이
두 번 울리고 화면 가장자리가 보라색으로 물듭니다 — 10초 뒤 밤입니다.

밤에는 **외계 거미**가 옵니다. 무적이고, 시야가 무한하고, 닿으면
즉사합니다. 싸울 수 없으니 계산이 "이길까"가 아니라 "돌아갈 수
있을까"가 됩니다. 캠프파이어 안으로는 못 들어오지만 경계에서
서성입니다 — 안전선이 눈에 보여야 "한 번만 더"가 유혹이 됩니다.

일출에 날짜가 오릅니다.

```
날짜 += 1 + 침대수 + 보유 핵심부품수
```

이 한 줄이 게임의 중심입니다. 침대를 여섯 개 깔고 핵심 부품을 넷 모으면
일출마다 **11일**이 지나가고, 100일이 46분 만에 옵니다. 대신 5의 배수
날짜를 한 번에 두세 개씩 넘기게 되고, **넘긴 개수만큼 소행성 회피
미니게임의 난이도가 오릅니다**. 빨리 가는 대가를 밤마다 치릅니다.

## 만들면서 내린 판단

기획서가 정하지 않았거나, 재 보니 다르게 해야 했던 것들입니다.

### 캠프파이어는 높은 등급부터 태운다

처음엔 낮은 등급부터 태웠습니다. "아껴 둔 기름이 통나무 태우는 동안
같이 줄면 억울하다"는 생각이었는데, 테스트가 §9.1 위반을 잡았습니다.

레벨은 "지금 타는 것 중 **최고** 등급"입니다. 낮은 것부터 태우면 기름이
맨 끝까지 남아서 그 시간 내내 Lv3 이고, 기름 하나로 밤을 통째로 사
버립니다. 기획서가 말한 "기름이 다 타면 통나무가 남아 있어도 즉시 Lv1"
이라는 순간이 영영 안 옵니다.

높은 것부터 태우니 기름 240초 동안 Lv3, 그 뒤로 뚝 떨어집니다. 그래야
밤에 나가기 전 무엇을 넣고 나갈지가 매번 판단이 됩니다.

### 부패를 "비율로 조금씩"으로 짰다가 틀렸다

통나무 10분 부패를 "10분에 전부"를 개수로 나눠 떼는 방식으로 짰습니다.
남은 개수가 줄수록 속도도 줄어서, **20개가 0이 되는 데 36분**이
걸렸습니다. 조화급수라 사실상 안 끝납니다.

지금은 들어온 시각별로 묶어서 셉니다. 10분 전에 들어온 묶음이 통째로
사라집니다. "10분 뒤에 사라진다"는 말이 말 그대로 성립하고, 나중에
주운 것은 나중에 썩습니다.

### 손전등에 배터리를 붙였다 (기획서 §0-3 확정안)

원본대로면 손전등이 무제한이라 횃불이 완전히 사장됩니다. 배터리 30초를
붙여서 역할을 갈랐습니다 — **손전등은 평시, 횃불은 비상**. 캠프 옆에서
20초면 충전됩니다.

### 크래프팅 4레벨의 존재 이유는 정비 도크다 (§8.5)

원본에는 4레벨을 찍을 이유가 없었습니다. **탈출선 정비 도크**를
4레벨에 두고 엔딩 필수로 만들면, 40나무/40고철짜리 업그레이드가 비로소
의미를 가집니다. 도크가 없으면 탈출 장비를 만들 수 없습니다.

### 연구소는 원형 교전장으로

기획서가 지하 내부 구조를 정하지 않았습니다. 탑다운에서 "못 나가는 원"이
잠긴 문을 가장 적은 그림으로 보여 줍니다. 규칙 둘은 그대로입니다 —
**전멸시켜야 열리고, 안에서는 밤 시간이 흐르지 않습니다.** 둘째 규칙이
없으면 3단계를 공략하다 밤을 맞고 문이 잠긴 채로 무조건 죽습니다.

### 기획서와 다르게 고른 것 둘

| 기획서 | 실제 | 이유 |
|---|---|---|
| seedrandom | 직접 만든 xorshift128 | 15줄이고, 갈래별 흐름 분리가 필요했습니다. 맵 생성기를 고쳐도 전리품 표가 안 밀리게 |
| Howler.js | Web Audio 직접 | 음원 파일이 하나도 없어서(전부 합성) 로더가 할 일이 없습니다. 공간 오디오와 로우패스는 Web Audio 기본 기능입니다 |

## §부록B — 기획서가 의심하라고 한 것들을 재 봤습니다

### 2번: 고철 410 / 통나무 270 이 100일 안에 모이는가

짐작하지 않고 실제 스폰 밀도를 세는 테스트를 넣었습니다.

```
맵 전체 매장량: 통나무 1848 · 고철 631
  1존: 통나무 198 · 고철  74
  2존: 통나무 564 · 고철 160
  3존: 통나무 630 · 고철 176
  4존: 통나무 456 · 고철 144
```

§12.2 의 목표치는 탈출 장비만 센 것이라, 도크(고철 80/나무 60)와 기계
업그레이드(70/70)와 침대(최대 120)를 더한 **런 전체 수요**로 보면
고철 550 · 통나무 520 입니다. 여유는 **고철 ×1.1 · 통나무 ×3.6**.

고철이 빠듯합니다. 1존 고철(74)은 수요의 13% 뿐이고 2존까지 훑어도
모자랍니다 — **3존까지 나가야 합니다.** 기획서가 노린 "존을 넓혀가야
하는 압박"은 고철이 만듭니다. 나무는 흔하지만 10분이면 썩으니 저장고를
먼저 지어야 합니다.

### 1번: 낮 3분이 파밍하기에 충분한가 — **넉넉합니다. 오히려 남습니다**

```
1존 왕복  4초 → 파밍 가능 176초
2존 왕복 13초 → 파밍 가능 167초
3존 왕복 23초 → 파밍 가능 158초
4존 왕복 29초 → 파밍 가능 151초
```

기획서는 "왕복 이동시간을 빼면 실제 파밍 시간은 1분 남짓일 수 있다"고
걱정했는데, 재 보니 정반대입니다. 맵 192타일 · 달리기 6.0 이면 가장 먼
4존도 왕복 29초입니다. **거리는 제약이 아닙니다.**

이 게임에서 낮을 조이는 것은 둘입니다.

- **가방 8칸** — 고철 550 을 모으려면 최소 18번 왕복해야 합니다
- **산소** — 4존은 1.5배로 마르므로 체류가 158초로 끊깁니다

기획서 수치를 그대로 지킨 결과이므로 임의로 바꾸지 않고 사실만 못 박아
두었습니다. 거리로 조이고 싶다면 맵을 키우거나 속도를 낮춰야 합니다.

### 3·4·5번은 아직 사람이 해 봐야 압니다

우주복 회복 불가가 너무 가혹한지, 호랑이가 재밌는지 짜증나는지, 침대
6개가 지배 전략인지는 숫자로 답할 수 없습니다. 다만 전부 `data/*.json`
한 줄이라 바꾸기 쉽게 해 두었습니다.

## 확인한 것

```bash
npm run check     # 린트 + 타입 + 로직 + 그리기
```

- **로직 56,119개** — 브라우저 없이 Node 에서 돕니다. 산소가 정확히
  4분에 마르는지, 캠프에서 우주복이 안 낫는지, 거미가 캠프 경계에서
  멈추는지, 같은 시드가 같은 세계를 만드는지, 12분을 굴려도 값이
  안 깨지는지.
- **그리기·UI 67개** — 호출을 받아 적는 가짜 캔버스에 낮·밤·연구소·
  질식·건물 열 종을 한 번씩 그려 봅니다. 로직이 5만 개 통과해도 화면이
  새까맣거나 HUD 가 안 뜨면 게임이 아니라서요. UI 는 linkedom 으로
  진짜 DOM 을 세워 HTML 을 만들어 봅니다(시험용 의존성).

### 테스트가 진짜 잡는지도 확인했습니다

구현을 **48가지**로 일부러 망가뜨려 봤습니다 — 거미를 캠프 안에
들이기, 불이 꺼져도 안 빨라지게 하기, 손전등을 무제한으로, 캠프에서
우주복이 낫게 하기, 침대 상한 없애기, 도크 없이 탈출 장비 만들기,
연구소를 전멸 전에 열기, 시드가 세계를 안 정하게 하기, 밸런스 JSON 에서
거미 속도를 뒤집기 등. **48개 모두** 테스트가 잡아냈습니다.

두 번은 처음에 놓쳤고, 그게 진짜 구멍이었습니다.

- **침대 상한을 다른 레시피로 우회할 수 있었습니다.** 침대는 레시피가
  넷(나무식·고철식·합금식·최상급)인데 테스트가 첫 번째만 지어 봤습니다.
  고철식으로 우회해 무한히 깔 수 있는지 아무도 안 물어봤던 겁니다.
- **연구소가 전멸 전에 열리는지 안 봤습니다.** 다 죽인 뒤에만 확인해서,
  "한 마리 남았을 때 안 열린다"는 정작 안 재고 있었습니다.

둘 다 테스트를 보태서 막았습니다.

## 구조

```
src/
  core/
    RNG.ts           시드 난수 · 갈래별 흐름 분리
    GameState.ts     런 하나 = 객체 하나. 죽으면 이것만 버린다
    Loop.ts          고정 60fps 로직 / 가변 그리기
    Input.ts         §3.1 키 매핑
    Audio.ts         Web Audio 합성 — 음원 파일 없음
    SaveData.ts      블랙박스만 저장. 런은 저장 안 한다
  data/              모든 수치가 여기 (§17.3)
    balance.json  items.json  recipes.json
    enemies.json  modifiers.json  unlocks.json
  world/
    Tilemap.ts       타일 좌표 · 원-원 충돌
    MapGen.ts        막는 것 목록
    Spawner.ts       존별 배치 밀도
    FogOfWar.ts      밝힌 곳이 아니라 밟은 곳
  systems/           전부 (state, dt) 만 받는다. DOM 을 모른다
    TimeSystem  SurvivalSystem  CampfireSystem  CraftingSystem
    CombatSystem  InventorySystem  DecaySystem  LabSystem  RunSystem
  entities/
    Player  Spider  Animal  Projectile
  minigame/
    AsteroidDodge.ts
  render/            Canvas 2D. 스프라이트 없이 도형으로만
    Renderer  Camera  Lighting  Effects
  ui/                DOM 오버레이
    HUD  Inventory  Lobby  Cutscene  DeathScreen
```

`systems/` 아래는 브라우저를 모릅니다. 그래서 테스트가 상태를 만들어
5만 번 굴려 볼 수 있고, 사망 시 "전부 사라진다"가 객체 하나 버리기로
끝납니다.
