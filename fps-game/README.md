# Bunker Break

브라우저에서 도는 1인칭 웨이브 서바이벌. 좁은 벙커에 파도처럼 밀려오는 적을
막아내며 몇 번째 웨이브까지 버티는지를 겨룬다.

```bash
npm install
npm run dev
```

모델·텍스처·음원 파일이 하나도 없다. 적도 무기도 맵도 Three.js 기본 도형으로
그 자리에서 만들고, 총소리는 Web Audio 로 합성한다. 받아올 것이 없으니
빌드 결과물만 있으면 어디서든 돈다.

## 조작

| 입력 | 동작 |
|---|---|
| W A S D | 이동 |
| 마우스 | 조준 |
| 좌클릭 | 발사 · 휘두르기 |
| R | 재장전 |
| Shift | 전력 질주 (전진할 때만) |
| Space | 점프 |
| 1 · 2 · 3 | 주무기 · 보조무기 · 근접무기 |
| 휠 · Q E | 가진 무기 순환 |
| Esc | 일시정지 |

시작하면 마우스가 화면에 잠긴다. Esc 로 풀면 자동으로 멈춘다.

## 규칙

**무기는 슬롯 셋**으로 나뉜다. 숫자키가 무기 이름이 아니라 역할을 가리켜서,
무엇을 주웠든 손이 찾는 자리가 바뀌지 않는다.

- **1 주무기** — 화력을 맡고 탄을 먹는다. 주워야 생긴다.
  돌격소총(2웨이브)과 샷건(4웨이브)이 이 자리를 나눠 쓴다. 둘 다 가지고
  있으면 1 을 다시 눌러 번갈아 꺼낸다 — 새로 주웠다고 쓰던 총을 잃지 않는다.
- **2 보조무기** — 권총. 예비탄이 무한해서 최후의 보루가 된다.
- **3 근접무기** — 전투 나이프. 탄약이라는 개념이 없고, 코앞 부채꼴 안을
  한 번에 벤다. 크롤러는 한 방. 탄을 아끼는 대신 적 무리 한가운데로
  들어가야 하는 무기다.

총은 헤드샷이 두 배. 근접은 헤드샷을 따지지 않는다 — 여럿을 동시에 베는데
누구는 머리고 누구는 몸통이라고 하면 같은 동작의 결과가 설명되지 않는다.

**적 셋**은 실루엣만 보고 구분되게 만들었다. 어두운 방에서 덩치만 보고
"저건 브루트다, 피해야 한다"가 즉시 나와야 한다.

- **크롤러** — 낮고 빠르다. 몰려온다. 눈높이로 쏘면 머리 위로 넘어간다.
- **트루퍼** — 멀리서 쏜다. 벽 뒤에서는 못 쏘고, 못 쏘면 다가온다.
- **브루트** — 느리고 단단하고, 맞으면 세게 밀린다.

**웨이브**는 번호에 대해 단조증가한다. 개체수는 상한에서 멈추고, 그 뒤로는
체력과 속도에 배율이 붙는다. 속도 배율에는 천장이 있다 — 가장 빠른 적도
플레이어보다 느려야 "물러나며 쏘기"가 계속 통한다.

**콤보**는 3초 안에 다음 처치가 이어질 때만 유지된다. 구석에서 한 마리씩
빼는 것보다 붙어서 몰아치는 쪽이 점수가 높다.

## 구조

```
src/
  game/            순수 규칙 — React 도 Three.js 도 모른다
    rng.js           씨앗 받는 난수 · 결정적 해시
    arena.js         맵 — 축에 나란한 상자 목록
    collide.js       원 대 상자 충돌 · 광선 판정 · 시야
    weapons.js       무기 수치
    combat.js        명중·피해·탄퍼짐
    enemies.js       적 수치와 상태 기계
    waveSpawner.js   난이도 곡선 · 스폰 일정
    score.js         점수·콤보·최고 기록
    player.js        이동·점프·사격·재장전
    session.js       위를 묶어 "한 판"을 굴린다
  three/           그리기 — game/ 의 상태를 받아 그리기만 한다
    Arena.jsx        바닥·벽·조명
    Enemy.jsx        절차적 적 모델 세 종
    Weapon.jsx       1인칭 뷰모델 + 총구 화염
    Effects.jsx      예광선·불꽃
    Pickups.jsx      보급품
    PlayerRig.jsx    카메라 ↔ 세션 ↔ 소리를 잇는 곳
  ui/              HUD 와 화면들 (DOM)
  hooks/useInput.js  키·마우스를 "뜻"으로 바꾼다
  audio.js         파일 없이 합성하는 소리
```

`game/` 은 브라우저 없이 그대로 돈다. 이게 이 프로젝트에서 제일 중요한 선이다 —
규칙이 렌더링에 얽혀 있으면 "체력이 0이면 정말 죽는가" 같은 것을 확인하려고
매번 게임을 켜서 손으로 쏴 봐야 한다.

## 테스트

```bash
npm test
```

- `test/logic.test.mjs` — 규칙 검증 **35,000여 개**. 벽 통과·터널링·적 끼임 같은
  것을 무작위 대량 시행으로 확인하고, 마지막에는 8웨이브를 봇으로 끝까지
  돌려 값이 깨지지 않는지 본다.
- `test/render.test.jsx` — 렌더링 계층 검증. R3F 테스트 렌더러로 씬을 머리 없이
  세우고 프레임을 돌려, 쏘면 실제로 죽고 그 사실이 UI 로 전달되는지까지 본다.

테스트가 실제로 잡는지도 확인했다. 구현을 **25가지**로 일부러 망가뜨려
(헤드샷 배율, 엄폐물 무력화, 터널링 부활, 적 길찾기 퇴행, 속도 상한 제거,
근접 부채꼴 판정 제거, 칼이 벽을 통과, 빈 슬롯으로 전환되어 빈손이 되기 등)
**25개 모두** 테스트가 잡아냈다.

변이 하나는 처음에 안 잡혔는데, 원인이 테스트가 아니라 코드였다. 나이프
탄창을 `Infinity` 로 두었더니 `Infinity - 1` 도 `Infinity` 라, "근접무기는
탄약을 안 쓴다"는 방어 코드를 지워도 아무 일이 없었다. 있으나 마나 한
코드였던 것이다. 탄창을 0 으로 바꾸니 그 방어 코드가 없으면 칼이 바로
먹통이 되고, 변이도 잡혔다.

## 기획서와 달라진 곳

`GAME_DESIGN.md` 는 물리 엔진(Rapier)을 쓰겠다고 적었지만 직접 짰다.
필요한 물리가 "벽을 못 지나간다" 하나뿐이고 맵이 전부 축에 나란한 상자라,
원-상자 밀어내기 60줄로 끝났다. 대신 얻은 것이 크다 — 순수 함수라 Node 에서
바로 검증되고, WASM 이 없어 번들과 로딩 실패 경로가 줄었다.

만들면서 기획서가 틀렸던 것도 하나 나왔다. 중앙 엄폐물을 십자로 두었더니
팔 사이 대각선 틈이 0.57 로, 플레이어 지름(0.72)보다 좁았다. 거기 낀 것은
양쪽에서 번갈아 밀려 밀어내기가 수렴하지 못하고 결국 벽을 뚫는다. 눈으로는
"좀 좁은 골목"으로만 보이는 배치가 물리를 깨뜨린 것이라, 지금은 상자 사이
틈이 0이거나 2.0 이상이어야 한다는 규칙을 테스트가 지킨다.
