# Bunker Break

브라우저에서 도는 1인칭 웨이브 서바이벌. 좁은 벙커에 파도처럼 밀려오는 적을
막아내며 몇 번째 웨이브까지 버티는지를 겨룬다. 양옆에 높은 통로가 있어,
계단으로 올라가 내려다보며 싸우거나 다시 내려와 붙을 수 있다.

들어가기 전에 **로비**에서 상대 실력 다섯 단계 중 하나를 고르고, 무기
**21자루** 중 주무기·보조무기·근접무기를 하나씩 골라 든다. 맵은 **열 장**
중 하나가 무작위로 나온다 — 고를 수 없다.

```bash
npm install
npm run dev
```

모델·텍스처·음원 파일이 하나도 없다. 적도 무기도 맵도 Three.js 기본 도형으로
그 자리에서 만들고, 총소리는 Web Audio 로 합성한다. 받아올 것이 없으니
빌드 결과물만 있으면 어디서든 돈다.

## 조작

| 입력 | 동작 |
|---|---|
| W A S D | 이동 |
| 마우스 | 조준 |
| 좌클릭 | 발사 · 휘두르기 |
| R | 재장전 |
| Shift | 전력 질주 (전진할 때만) |
| Space | 점프 |
| 1 · 2 · 3 | 주무기 · 보조무기 · 근접무기 |
| 휠 · Q E | 가진 무기 순환 |
| Esc | 일시정지 |

시작하면 마우스가 화면에 잠긴다. Esc 로 풀면 자동으로 멈춘다.

## 규칙

**무기 스물한 자루가 슬롯 셋**으로 나뉜다. 숫자키가 무기 이름이 아니라
역할을 가리켜서, 무엇을 골랐든 손이 찾는 자리가 바뀌지 않는다.

수치만 조금씩 다른 총을 늘리면 고를 것이 많아지는 게 아니라 고르기
귀찮아질 뿐이라, **방아쇠를 당겼을 때 벌어지는 일 자체**를 다섯 갈래로
나눴다.

| 방식 | 무기 |
|---|---|
| 단발 · 연사 | 카빈 · 돌격소총 · 샷건 · 자동샷건 · 경기관총 · 저격총 · 권총 · 소음권총 · 매그넘 · 쌍권총 · 기관단총 · 자동권총 |
| **점사** | 배틀라이플 · 점사권총 — 한 번 누르면 세 발이 나가고 쉰다 |
| **예열** | 미니건 — 누르고 있으면 점점 빨라진다. 미리 돌려 두는 판단 |
| **차지** | 레일건 — 모았다 놓는다. 다 모으면 3.4배, 한 줄을 통째로 지운다 |
| **근접** | 나이프 · 쇠파이프 · 카타나 · 도끼 · 대형 망치 — 탄약이 없다 |

한 자리를 여럿이 나눠 쓰고, 같은 숫자를 다시 누르면 그 안에서 교대한다.

총은 헤드샷이 두 배. 근접은 헤드샷을 따지지 않는다 — 여럿을 동시에 베는데
누구는 머리고 누구는 몸통이라고 하면 같은 동작의 결과가 설명되지 않는다.

히트스캔이 아닌 것이 둘 있다.
- **근접** — 광선 하나로는 발밑의 크롤러를 자꾸 놓친다. 사거리·부채꼴·시야를
  만족하는 적을 **가까운 순으로 정해진 수까지** 벤다. 거리는 몸 중심이 아니라
  표면까지로 재서, 브루트가 몸을 맞대고 있으면 실제로 닿는다.

  한때 근접이 압도적이었다. 부채꼴 안을 **전부**, 탄약도 없이 베어서 다섯에
  둘러싸이면 초당 400 이 나왔다 — 탄을 먹는 최고 주무기(303)보다 나았으니
  다른 것을 쥘 이유가 없었다. 지금은 무기마다 벨 수 있는 수에 상한(2~4)이
  있고 뒤로 갈수록 약해진다. 단일 대상 화력은 권총보다도 낮다. 근접의
  값어치는 화력이 아니라 "탄약을 안 쓰고 둘셋을 한 번에"에 있다.
- **관통** — 저격총은 가까운 순으로 셋까지 뚫고, 레일건은 줄 전체를 뚫는다.
  뒤로 갈수록 약해져서, 줄을 세워 쏘는 판단이 값을 하되 무한정 세지지 않는다.

## 맵 열 장

판마다 하나가 무작위로 뽑힌다. 아레나 크기(30×30)와 담장은 모두 같고,
안에 무엇이 서 있는지만 다르다.

| | 맵 | 성격 |
|---|---|---|
| 벙커 | 중앙 광장 + 양옆 통로 | 높은 자리와 네 귀퉁이 입구 |
| 십자로 | 담장까지 뻗은 십자 벽 | 중앙을 거치지 않으면 못 넘어간다 |
| 회랑 | 가운데를 두른 두꺼운 벽 | 네 귀퉁이에만 문 |
| 기둥숲 | 기둥 열여섯 | 트여 있고 빠르다 |
| 참호 | 나란한 긴 벽 | 끝까지 돌아야 넘어간다 |
| 투기장 | 가장자리를 두른 관람석 | 가운데는 완전히 트였다 |
| 미로 | 엇갈린 벽 | 코너마다 무엇이 있을지 모른다 |
| 탑 | 가운데 솟은 단 | 다 보이지만 사방에서 올라온다 |
| 분할 | 가운데를 가르는 벽 | 넘어가려면 양끝 통로를 거친다 |
| 개활지 | 숨을 곳이 거의 없다 | 거리로만 버틴다 |

배치는 취향 문제처럼 보이지만 실제로는 물리를 깨뜨린다. 그래서 넷을
**열 장 모두**에 대해 테스트가 검사한다.

1. 막는 상자 사이의 틈은 0(붙어 있음)이거나 2.0 이상 — 어중간한 틈에
   낀 것은 양쪽에서 번갈아 밀려 결국 벽을 뚫는다
2. 통로는 바닥에서 점프해 못 닿아야 한다 — 닿으면 계단이 장식이 된다
3. 엄폐물은 통로에서 점프해도 못 올라갈 높이 — 적이 못 닿는 자리가
   생기면 그 판은 거기서 끝난다
4. **모든 스폰 지점에서 플레이어에게 닿는 길이 있어야 한다** — 실제로
   적을 걸려 보게 해서 확인한다

만들면서 이 검사가 다섯 장에서 결함을 잡아냈다. 그중 둘은 눈으로는
멀쩡해 보이는 것이었다 — 회랑은 벽 넷이 서로 겹쳐 **완전히 닫힌 고리**가
되어 안에 선 플레이어에게 적이 영영 못 왔고, 탑은 단이 시작 자리를 덮어
플레이어가 지형 속에서 판을 시작했다.

## 상대 실력 다섯 단계

로비에서 고른다. 적의 체력·피해·수·명중률과 플레이어 회복 속도가 한꺼번에
움직인다.

| 단계 | 체력 | 피해 | 수 | 명중률 | 회복 |
|---|---|---|---|---|---|
| 초급 | ×0.65 | ×0.55 | ×0.65 | ×0.6 | ×1.6 |
| 중급 | ×1 | ×1 | ×1 | ×1 | ×1 |
| 고급 | ×1.35 | ×1.3 | ×1.25 | ×1.2 | ×0.7 |
| 익스트림 | ×1.85 | ×1.75 | ×1.5 | ×1.4 | ×0.35 |
| 신화 | ×2.6 | ×2.3 | ×1.8 | ×1.65 | **없음** |

중급이 기준이고 나머지는 전부 거기서 재고 뺀 것이다 — 그래야 "고급이
중급보다 얼마나 어려운가"가 표 하나로 읽힌다.

속도만은 따로 천장을 씌운다. 웨이브 배율과 난이도 배율이 곱해지면 신화
후반에서 크롤러가 플레이어를 따라잡는데, 그러면 "물러나며 쏘기"가 통하지
않게 된다. 어려워지는 게 아니라 대응할 방법이 사라지는 것이라, 어떤
단계·어떤 웨이브에서도 가장 빠른 적이 플레이어보다 느리도록 잘라 둔다.

가만히 서서 보이는 적만 쏘는 봇으로 재 보면 단계별로 평균 **15.3 · 8.3 ·
6.5 · 5.0 · 3.5** 웨이브다. 맵 열 장 사이의 편차도 6.0~6.7 로 고르다 —
어느 맵이 나와도 난이도가 크게 흔들리지 않는다.

**적 셋**은 실루엣만 보고 구분되게 만들었다. 어두운 방에서 덩치만 보고
"저건 브루트다, 피해야 한다"가 즉시 나와야 한다.

- **크롤러** — 낮고 빠르다. 몰려온다. 눈높이로 쏘면 머리 위로 넘어간다.
- **트루퍼** — 멀리서 쏜다. 벽 뒤에서는 못 쏘고, 못 쏘면 다가온다.
  사거리는 아레나 절반보다 짧아서, 물러나면 벗어날 수 있다.
- **브루트** — 느리고 단단하고, 맞으면 세게 밀린다.

적의 사거리는 높이까지 넣어 잰다. 통로 아래에 선 크롤러가 2미터 위를 무는
일은 없다 — 그러면 높은 자리를 만든 이유가 사라진다.

**높이**가 판을 가른다. 양옆 통로(높이 2)는 계단으로만 오른다 — 바닥에서
점프해서는 닿지 않는다. 올라서면 광장 벽 너머가 보이고, 바닥에 선 적은
손이 닿지 않는다. 다만 안전지대는 아니다: 적도 같은 계단으로 올라온다.
올라간 값은 시야이지 무적이 아니다.

**웨이브**는 번호에 대해 단조증가한다. 개체수는 상한에서 멈추고, 그 뒤로는
체력과 속도에 배율이 붙는다. 속도 배율에는 천장이 있다 — 가장 빠른 적도
플레이어보다 느려야 "물러나며 쏘기"가 계속 통한다.

**체력은 한동안 안 맞으면 서서히 찬다.** 이게 없으면 열 번째 웨이브의
난이도가 열 번째 웨이브의 실력이 아니라 첫 웨이브에서 실수했는지로 정해진다.
교전 중에는 안 차므로, 물러나 숨을 돌릴지가 판단이 된다.

**콤보**는 3초 안에 다음 처치가 이어질 때만 유지된다. 구석에서 한 마리씩
빼는 것보다 붙어서 몰아치는 쪽이 점수가 높다.

## 구조

```
src/
  game/            순수 규칙 — React 도 Three.js 도 모른다
    rng.js           씨앗 받는 난수 · 결정적 해시
    arena.js         모든 맵이 공유하는 것 — 크기·담장·상자 만들기
    maps.js          맵 열 장 · 무작위 뽑기
    collide.js       원 대 상자 충돌 · 발밑 높이 · 광선 판정 · 시야
    weapons.js       무기 스물한 자루 · 발사 방식
    difficulty.js    다섯 단계 배율 · 속도 천장
    combat.js        명중·피해·탄퍼짐
    enemies.js       적 수치와 상태 기계
    waveSpawner.js   난이도 곡선 · 스폰 일정
    score.js         점수·콤보·최고 기록
    player.js        이동·점프·사격·재장전
    session.js       위를 묶어 "한 판"을 굴린다
  three/           그리기 — game/ 의 상태를 받아 그리기만 한다
    Arena.jsx        바닥·벽·조명
    Enemy.jsx        절차적 적 모델 세 종
    weaponMaterials.js  강철·폴리머·나무·놋쇠 …
    weaponParts.jsx  총열·탄창·레일·가늠쇠 같은 조각들
    Weapon.jsx       그 조각으로 조립한 무기 스물한 자루 + 총구 화염
    Effects.jsx      예광선·불꽃
    Pickups.jsx      보급품
    PlayerRig.jsx    카메라 ↔ 세션 ↔ 소리를 잇는 곳
  ui/
    Lobby.jsx        난이도와 무기 셋을 고르는 곳
    Hud.jsx          체력·탄약·예열·차지 게이지
    Screens.jsx      메뉴 · 일시정지 · 게임오버
  hooks/useInput.js  키·마우스를 "뜻"으로 바꾼다
  audio.js         파일 없이 합성하는 소리
```

`game/` 은 브라우저 없이 그대로 돈다. 이게 이 프로젝트에서 제일 중요한 선이다 —
규칙이 렌더링에 얽혀 있으면 "체력이 0이면 정말 죽는가" 같은 것을 확인하려고
매번 게임을 켜서 손으로 쏴 봐야 한다.

## 테스트

```bash
npm test
```

- `test/logic.test.mjs` — 규칙 검증 **66,000여 개**. 벽 통과·터널링·적 끼임·
  공중 걷기 같은 것을 무작위 대량 시행으로 확인하고, **맵 열 장 × 스폰
  지점 × 적 세 종**이 전부 플레이어에게 닿는지 실제로 걸려 보고, 주무기×
  보조×근접 **315가지 조합**이 전부 굴러가는지 보고, 마지막에는 8웨이브를
  봇으로 끝까지 돌려 값이 깨지지 않는지 본다.
- `test/render.test.jsx` — 렌더링 계층 검증. R3F 테스트 렌더러로 씬을 머리 없이
  세우고 프레임을 돌려, 쏘면 실제로 죽고 그 사실이 UI 로 전달되는지까지 본다.

테스트가 실제로 잡는지도 확인했다. 구현을 **81가지**로 일부러 망가뜨려
(헤드샷 배율, 엄폐물 무력화, 터널링 부활, 적 길찾기 퇴행, 속도 상한 제거,
근접 부채꼴 판정 제거, 칼이 벽을 통과, 관통이 엉뚱한 적을 뚫기, 무기 하나를
영영 못 쥐게 만들기, 공중을 걷게 만들기, 계단을 못 오르게 만들기,
난이도 다섯 단계를 전부 같게 만들기, 차지를 놓기 전에 나가게 하기,
맵 하나의 문을 닫아 막다른 길로 만들기, 근접 상한을 없애 다시 사기로
만들기 등) **81개 모두** 테스트가 잡아냈다.

안 잡힌 변이가 몇 번 있었는데, 매번 배울 게 있었다.

**한 번은 코드가 문제였다.** 나이프 탄창을 `Infinity` 로 두었더니
`Infinity - 1` 도 `Infinity` 라, "근접무기는 탄약을 안 쓴다"는 방어 코드를
지워도 아무 일이 없었다. 있으나 마나 한 코드였던 것이다. 탄창을 0 으로
바꾸니 그게 없으면 칼이 바로 먹통이 되고, 변이도 잡혔다.

**한 번은 테스트가 문제였다.** 관통 시험에서 적을 가까운 순으로 만들어
넣었더니, "가까운 순으로 정렬" 코드를 통째로 지워도 통과했다. 이미 정렬된
것을 정렬해 봐야 티가 안 난다. 실제 게임의 적 배열은 스폰 순서지 거리
순이 아니므로, 섞어 넣도록 고치니 잡혔다.

**한 번은 기준이 헐거워서 아무것도 못 걸렀다.** 근접이 총보다 세면 안
된다는 것을 "최고 총(미니건 303)보다 낮다"로 검사했더니, 너프 전의 사기
수치(74)도 여유롭게 통과했다. 미니건은 예외적으로 센 무기라 기준이 될 수
없다. "최후의 보루인 권총(66)보다도 낮다"로 바꾸니 잡혔다 — 근접의
값어치는 화력이 아니니 그 기준이 뜻도 맞다.

**한 번은 시험이 재려던 것을 다른 것이 가리고 있었다.** 점사 사이에 쉼이
있는지 보려고 발사 간격을 쟀는데, 탄창이 비어 재장전(1.4초)이 끼는 바람에
그게 늘 "가장 긴 간격"이 됐다. 쉼을 없애도 통과한 이유다 — 탄창이 남아
있는 동안만 재도록 고쳤다.

**한 번은 시험 자체가 불가능한 상황을 만들고 있었다.** 높이가 생긴 뒤,
"아래에 선 적이 위를 못 때린다"를 확인하려고 적을 계단 한가운데에 y=0 으로
놓았다. 지형 속에 파묻힌 자리라, 밀어내기가 통로 안쪽으로 밀어내며 있을
수 없는 위치에서 때렸다. 게임의 결함이 아니라 시험이 만든 상황이었다 —
진짜 바닥에 세우니 통과했다.

## 기획서와 달라진 곳

`GAME_DESIGN.md` 는 물리 엔진(Rapier)을 쓰겠다고 적었지만 직접 짰다.
필요한 물리가 "벽을 못 지나간다" 하나뿐이고 맵이 전부 축에 나란한 상자라,
원-상자 밀어내기 60줄로 끝났다. 대신 얻은 것이 크다 — 순수 함수라 Node 에서
바로 검증되고, WASM 이 없어 번들과 로딩 실패 경로가 줄었다.

만들면서 기획서가 틀렸던 것도 하나 나왔다. 중앙 엄폐물을 십자로 두었더니
팔 사이 대각선 틈이 0.57 로, 플레이어 지름(0.72)보다 좁았다. 거기 낀 것은
양쪽에서 번갈아 밀려 밀어내기가 수렴하지 못하고 결국 벽을 뚫는다. 눈으로는
"좀 좁은 골목"으로만 보이는 배치가 물리를 깨뜨린 것이라, 지금은 상자 사이
틈이 0이거나 2.0 이상이어야 한다는 규칙을 테스트가 지킨다.
