# FPS 게임 기획서 — "Bunker Break"

> **이 기획서는 구현되었다.** 실제로 만들어진 것과 이 문서가 다른 곳은
> 12절에 정리해 두었다. 돌려 보려면 `README.md` 를 보라.

이 문서는 그 자체로 **빌드 프롬프트**다. 이 문서 하나만 가지고 처음부터
실제로 동작하는 게임을 만들 수 있도록, 기술 스택·파일 구조·각 시스템의
동작 방식·완료 기준까지 전부 못박아 둔다. 애매한 "재미있게 만들어 주세요"
류의 문장은 없다 — 전부 코드로 옮길 수 있는 구체적인 규칙이다.

## 0. 한 줄 요약

브라우저에서 마우스로 조준하고 클릭으로 쏘는 **1인칭 웨이브 서바이벌**.
좁은 벙커형 아레나에 파도(웨이브)로 몰려오는 적을 막아내며 최대한
오래 버틴다. 외부 3D 모델·텍스처·사운드 파일은 하나도 쓰지 않는다 —
`my-dragon-game`이 절차적 지오메트리로 용을 만든 것처럼, 여기서도
Three.js 기본 도형만으로 적·무기·맵을 만든다.

왜 웨이브 서바이벌인가: 오픈월드나 스토리 기반 FPS는 레벨 디자인·내러티브
자산이 방대해 "직접 만들 수 있는 프롬프트"라는 제약을 못 지킨다. 아레나 +
웨이브 구조는 맵 하나, 적 종류 서너 개, 무기 서너 개로 게임 하나가
완결되므로 실제로 한 번의 빌드 세션 안에 끝까지 만들 수 있다.

## 1. 기술 스택 (기존 저장소와 동일하게 맞춘다)

`my-3d-game`, `my-dragon-game`과 동일한 스택을 쓴다 — 새 도구를 배우거나
검증되지 않은 라이브러리를 추가하지 않는다.

- React 19 + Vite + `@react-three/fiber` ^9 + `@react-three/drei` ^10 + `three` ^0.185
- **추가 의존성 1개만 허용**: `@react-three/rapier` (WASM 물리 엔진).
  이유: FPS 캐릭터 충돌(벽에 안 끼기, 계단·경사 처리, 넉백)을 손으로
  짜면 버그가 끝없이 나온다. Rapier의 캡슐 콜라이더 + `KinematicCharacterController`
  하나로 이 문제 전체를 표준적인 방식으로 해결한다. 그 외 총쏘기·데미지·
  스폰 로직은 전부 순수 JS로 직접 짠다.
- Tailwind v4 — HUD(체력바, 탄약, 웨이브 표시)는 DOM 오버레이로, 3D 캔버스
  위에 절대좌표로 얹는다 (Three.js 안에서 텍스트 렌더링하지 않는다 —
  DOM이 더 빠르고 정확하다).
- 조준/이동: `@react-three/drei`의 `PointerLockControls` (이미 의존성에
  있음) — 브라우저 Pointer Lock API로 마우스를 캡처해 시점 회전.
- 사운드: 외부 파일 없이 Web Audio API 오실레이터로 직접 합성
  (`coding-ai`의 `beepJs` 패턴과 동일한 철학). 총소리는 짧은 노이즈
  버스트 + 저역 필터, 피격음은 사각파 클릭.
- 배포: 기존과 동일하게 `npm run build` → `git worktree add .gh-pages-wt
  gh-pages` → `dist/*`를 `fps-game/` 서브폴더로 복사 → 커밋·푸시.

## 2. 프로젝트 구조

```
fps-game/
  package.json
  vite.config.js
  index.html
  src/
    main.jsx
    App.jsx                 화면 전환: 메뉴 → 플레이 → 일시정지 → 게임오버
    game/                    순수 로직 — React/Three 모름, Node에서 바로 테스트
      weapons.js             무기 스탯(피해량·연사속도·탄창·재장전시간·탄퍼짐)
      combat.js               데미지 계산, 헤드샷 배율, 명중 판정 순수함수
      enemies.js               적 종류별 스탯(체력·이동속도·공격력·점수)
      waveSpawner.js           웨이브 난이도 곡선 — n번째 웨이브에 뭐가 몇 마리
      aiState.js                적 AI 상태머신 순수함수: idle→chase→attack→dead
      arena.js                  맵 레이아웃 데이터(벽·엄폐물 좌표) — 절차적 생성
      score.js                  점수·콤보 계산, localStorage 최고기록
    three/                   렌더링 — 위 game/*.js 의 상태를 받아 그리기만 함
      Player.jsx                Rapier 캡슐 캐릭터 컨트롤러 + PointerLockControls
      Weapon.jsx                 1인칭 시점 무기 모델(절차적 지오메트리) + 반동 애니메이션
      Enemy.jsx                   적 3D 모델(절차적 지오메트리) + AI 상태에 따른 애니메이션
      Arena.jsx                   맵 지오메트리(바닥·벽·엄폐물·조명)
      MuzzleFlash.jsx             총구 화염·탄피 파티클(간단한 스프라이트)
      Bullet.jsx                  히트스캔이라 실제 투사체 없음 — 트레이서 선만 잠깐 그림
    ui/                      HUD — DOM, Tailwind
      Crosshair.jsx
      HealthBar.jsx
      AmmoCounter.jsx
      WaveBanner.jsx             "웨이브 3 시작" 같은 안내
      GameOverScreen.jsx          최종 점수 · 다시하기
      MainMenu.jsx
    hooks/
      usePointerLock.js
      useGameLoop.js            게임 상태(웨이브 진행, 스폰 타이머)를 매 프레임 갱신
```

`game/`과 `three/`·`ui/`를 분리하는 이유는 기존 저장소 전체(용 게임의
`battle.js`/`fx.js`, coding-ai의 `brain/`/`generate/`)에서 이미 검증된
패턴이다: 순수 로직은 `node --input-type=module -e "import(...)"` 로
브라우저 없이 바로 테스트할 수 있어야 하고, 렌더링 코드는 그 결과를
받아 그리기만 해야 한다.

## 3. 핵심 게임플레이 루프

1. 메인 메뉴 → "시작" 클릭 → Pointer Lock 활성화, 웨이브 1 시작
2. 화면 중앙 크로스헤어로 조준, 좌클릭으로 발사(히트스캔 레이캐스트)
3. 적이 아레나 가장자리 스폰 지점에서 나타나 플레이어를 향해 이동
4. 적을 전부 처치하면 다음 웨이브까지 5초 휴식(그 사이 탄약 픽업 가능)
5. 플레이어 체력이 0이 되면 게임오버 → 최종 점수·최고기록 표시 → 다시하기
6. Esc로 언제든 일시정지(Pointer Lock 해제), 클릭하면 재개

승리 조건은 없다 — "몇 웨이브까지 버텼는가"가 곧 점수다. 이렇게 하면
엔딩 컷신이나 스토리 분기 같은, 손으로 만들기 힘든 콘텐츠가 필요 없다.

## 4. 조작

| 입력 | 동작 |
|---|---|
| W/A/S/D | 이동 (Rapier 캐릭터 컨트롤러, 벽 슬라이딩 자동 처리) |
| 마우스 이동 | 시점 회전 (Pointer Lock, 감도 옵션 하나) |
| 좌클릭 | 발사 |
| R | 재장전 |
| Shift | 스프린트 (이동속도 1.6배, 조준 정확도 하락) |
| Space | 점프 |
| 1 / 2 / 3 | 무기 전환 |
| Esc | 일시정지 |

## 5. 무기 (전부 히트스캔 — 투사체 시뮬레이션 없이 레이캐스트로 즉시 판정)

`game/weapons.js`에 다음 3종을 하드코딩한 상수 테이블로 정의:

| 무기 | 피해량 | 연사속도(발/초) | 탄창 | 재장전(초) | 탄퍼짐(도) | 특징 |
|---|---|---|---|---|---|---|
| 권총 (기본, 무한 탄약) | 22 | 3 | 12 | 1.0 | 1 | 시작 무기, 탄 걱정 없음 |
| 돌격소총 (웨이브 2부터 픽업) | 15 | 8 | 30 | 2.0 | 3 | 연사, 근거리 유리 |
| 샷건 (웨이브 4부터 픽업) | 60 (탄환 8개 분산, 개당 7.5) | 1.2 | 6 | 2.5 | 12 | 근거리 학살, 원거리 비효율 |

헤드샷 배율 2.0배 (`combat.js`의 순수함수 `applyDamage(base, isHeadshot)`로
계산 — 히트박스는 적 모델의 상단 30%를 "머리"로 판정).

무기 픽업은 아레나에 절차적으로 배치된 회전하는 도형(예: 소총은 회전하는
사각기둥)으로 표현, 플레이어가 3유닛 이내로 접근하면 자동 획득.

## 6. 적 (전부 절차적 지오메트리 — 외부 모델 없음)

`game/enemies.js`에 종류별 스탯, `three/Enemy.jsx`에서 지오메트리로 표현.
용 게임에서 `hash32`로 종족별 생김새를 절차적으로 갈랐던 것처럼, 여기서도
적 ID로부터 결정적으로 크기·색을 미세하게 흔들어 같은 종류라도 완전히
똑같아 보이지 않게 한다.

| 종류 | 체력 | 이동속도 | 공격 | 등장 웨이브 | 지오메트리 컨셉 | 점수 |
|---|---|---|---|---|---|---|
| 크롤러 | 30 | 빠름 | 근접(닿으면 지속 데미지) | 1부터 | 낮게 웅크린 사면체 뭉치, 다리 대신 관절 실린더 | 10 |
| 트루퍼 | 60 | 보통 | 원거리(단발 히트스캔, 명중률 낮음) | 2부터 | 캡슐 몸통 + 상자 헤드, 총처럼 보이는 실린더를 든 모양 | 20 |
| 브루트 | 150 | 느림 | 근접(넉백 있는 강타) | 3부터 | 커다란 각진 상자 뭉치, 위협적으로 크게 | 40 |

적 AI는 `game/aiState.js`의 순수 상태머신:
`idle`(스폰 직후 잠깐) → `chase`(플레이어 방향으로 이동) →
`attack`(사거리 안이면 쿨다운마다 공격) → `dead`(체력 0, 점수 지급 후
1초 뒤 제거). 각 전이 조건은 거리·타이머만으로 결정되는 순수함수라
Node에서 "체력을 깎으면 dead로 간다" 같은 것을 바로 테스트할 수 있다.

## 7. 웨이브 스폰

`game/waveSpawner.js`의 `waveComposition(waveNumber)` 순수함수가 웨이브당
적 구성을 반환한다. 난이도 곡선(초안, 실제 수치는 플레이테스트로 미세조정
가능하되 함수 시그니처와 단조증가 성질은 고정):

```
crawlers = min(4 + waveNumber * 2, 20)
troopers = waveNumber >= 2 ? min((waveNumber - 1) * 2, 12) : 0
brutes   = waveNumber >= 3 ? floor((waveNumber - 2) / 2) : 0
```

스폰 지점은 아레나 가장자리에 미리 정의된 4~6개 지점 중 매 스폰마다
무작위 선택 — 한 곳에 몰리지 않게 최소 두 지점을 번갈아 쓴다.

## 8. 맵 ("벙커")

단일 아레나, 약 30×30 유닛. 완전한 사각형 대신 중앙에 십자형 엄폐물
벽 2~3개를 배치해 시야를 끊고 근접전을 유도한다. 전부 `arena.js`의
좌표 배열로 정의하고 `Arena.jsx`가 박스 지오메트리로 그린다 — 레벨
에디터나 외부 포맷은 쓰지 않는다. 벽에는 Rapier의 고정(fixed) 콜라이더를
붙여 플레이어·적 모두 통과하지 못하게 한다.

## 9. HUD

- 좌하단: 체력바 (0~100, 낮을수록 빨간색 + 화면 가장자리 붉은 비네트)
- 우하단: 현재 탄창/예비 탄약, 무기 아이콘(간단한 도형)
- 상단 중앙: 웨이브 배너 ("웨이브 3" 이 2초간 페이드 인/아웃)
- 중앙: 크로스헤어 (발사 시 살짝 벌어졌다가 복귀)
- 좌상단: 점수, 처치 수

## 10. 판정 로직 (순수함수로 분리 — 이게 테스트의 핵심)

- `combat.raycastHit(origin, direction, enemies)` — Three.js에 의존하지
  않는 순수 벡터 수학으로 가장 가까운 피격 대상 계산 (렌더링 코드에서는
  Three.js `Raycaster`를 실제로 쓰되, 판정 자체의 단위 테스트는 이
  순수함수로 한다)
- `combat.applyDamage(weapon, isHeadshot, armor)` — 최종 데미지
- `enemies.tick(enemy, playerPos, dt)` — AI 한 프레임 갱신, 새 상태 반환
- `waveSpawner.waveComposition(n)` — 위 3번 공식
- `score.recordKill(state, enemyType, isHeadshot)` — 점수·콤보 갱신

이 5개 함수 세트가 게임의 "규칙"이며, `coding-ai`에서 했던 것과 동일한
방식으로 Node에서 file:// import 해서 단위 테스트를 짠다:
- 웨이브 구성이 웨이브 번호에 대해 단조증가하는지
- 헤드샷이 정확히 2배 데미지인지
- 체력이 정확히 0 이하로 떨어질 때만 dead로 전이하는지 (음수 체력 방치 금지)
- 레이캐스트가 엄폐물 뒤 적을 못 맞히는지 (벽이 시야를 가리는지)
- 최고기록이 localStorage에 실제로 저장/복원되는지

## 11. 완료 기준 (Definition of Done)

- `npm run build`가 에러 없이 끝난다
- 위 5개 순수함수에 대한 단위 테스트가 전부 통과한다 (Node, 브라우저 없이)
- 메뉴 → 플레이 → 일시정지 → 재개 → 게임오버 → 다시하기 흐름이 끊기지
  않는다
- 웨이브 1~5까지 실제로 플레이해서 난이도가 급격히 튀거나 적이 스폰
  안 되는 구간이 없는지 확인한다
- 기존 `gh-pages` 브랜치의 다른 프로젝트(용 게임, coding-ai)를 건드리지
  않고 `fps-game/` 서브폴더로만 배포된다

## 12. 만들면서 기획서와 달라진 것

기획서는 만들기 전에 쓴 글이라, 실제로 짜 보면 틀린 곳이 나온다.
고친 것을 여기 남긴다 — 문서와 코드가 다르면 문서 쪽이 거짓말이 된다.

**물리 엔진을 안 썼다.** 1절에서 Rapier(WASM)를 유일한 추가 의존성으로
허용했지만, 직접 짜는 쪽으로 바꿨다. 이 게임에 필요한 물리는 "벽을 못
지나간다" 하나뿐이고 아레나가 전부 축에 나란한 상자라, 원-상자 밀어내기
60줄로 끝난다. 직접 짜서 얻은 것이 더 크다 — 순수 함수라 Node 에서 바로
검증되고(이 저장소가 지켜 온 "규칙은 순수 함수로" 원칙을 안 깬다),
WASM 이 없어 번들과 로딩 실패 경로가 줄었다. → `src/game/collide.js`

**중앙 엄폐물 배치가 틀렸다.** 8절의 "중앙 십자형" 을 그대로 놓았더니
팔 사이 대각선 틈이 0.57 이었다. 플레이어 지름이 0.72 이라 그 틈에는
못 들어가는데, 밀려 들어가면 양쪽에서 번갈아 밀려 밀어내기가 수렴하지
못하고 결국 벽을 뚫는다. 지금은 중앙 광장을 두르는 벽 넷을 떨어뜨려
네 귀퉁이에 대각선 통로를 냈고, "상자 사이 틈은 0이거나 2.0 이상"이라는
규칙을 테스트가 지킨다.

**트루퍼는 물러나지 않는다.** 6절에는 원거리 적이 선호 거리를 유지하도록
적었는데, 뒷걸음질하게 두면 뒤가 엄폐물일 때 그 안으로 파고들어 자리를
잡는다. 플레이어가 반격할 수 없는 자리에서 계속 쏘는 교착이 된다.
지금은 멀면 다가오되 가까워도 물러나지 않는다.

**시야는 몸 한가운데에서 잰다.** 눈높이로 재면 "나는 보이는데 너는 나를
못 맞히는" 자리가 생긴다. 플레이어가 겨누는 지점(몸 중심)과 같은 점을
쓰면 그런 자리가 아예 안 생긴다.

**적 속도 상한을 1.35 → 1.18 로 낮췄다.** 7절 수치대로면 후반 크롤러가
플레이어보다 빨라져서(4.3 × 1.35 = 5.8 > 5.2) 도망칠 방법이 사라진다.

**추가한 것**: 콤보 점수, 보급품(탄약·체력), 웨이브 사이 준비 시간,
피격 무적 0.28초(크롤러에 둘러싸였을 때 한 프레임에 세 번 맞아 녹는 것을
막는다), 마우스 잠금 실패 안내.
